# Recon: Muthukumar-Selvarasu/agentic-semantic-search

Sources fetched (not the .mp4): `README.md`, `SUMMARY.md`, `LINEAR_TASKS.md`, `app.py`, `requirements.txt`, `live_test.ipynb`, and slide text extracted from `Semantic-Search-to-Moment-Search.pptx`. All saved under `.../scratchpad/muthukumar/`.

**1. Video chosen:** Steve Jobs' 2005 Stanford commencement address (`UF8uR6Z6KLc`), 244 English captions. Reason stated: one talk with three distinct stories plus a closing charge, separated by pauses and topic cues ("my third story is about death") — gives both baseline and moment approaches the same questions to answer, testing whether chunking respects idea boundaries.

**2. Baseline:** Transcript via `youtube-transcript-api` (falls back to an embedded 4-topic lecture if YouTube blocks the request). Chunking: captions joined into one string, cut every 250 characters with 50-character overlap — character-offset cuts, so they can split mid-word/mid-sentence (61 windows for this talk, all 61 break a sentence edge, per his claim). Embeddings: `sentence-transformers/all-MiniLM-L6-v2`. Vector store: ChromaDB (`baseline_collection`), local, written to `chroma_db/`. "Answer" generation: **no LLM** — top-3 windows retrieved and stitched in time order with `[...]` gap markers; this is a formatted extractive answer, not generation. No OpenAI/Anthropic dependency anywhere in `requirements.txt` or `app.py`.

**3. Moment RAG:** Algorithm (rule-based, not LLM-detected): walk captions in order; open a new moment when the gap since the previous caption is ≥2 seconds, OR the next caption starts with a topic cue ("the first story", "my second story", etc.); a 120-second cap forces a split (on a caption boundary) so no single silence can swallow the whole video. No LLM prompt involved in moment detection. Metadata per moment: `start_time`, `end_time`, `moment_summary` (the opening sentence), full text stored in `moment_collection` (same embedding model/Chroma). Retrieval difference: returns the *entire* top-1 moment's text as the answer (not top-3 merged); other hits are listed but excluded from the answer text — this talk yields 15 moments.

**4. Comparison:** Two benchmark questions — (1) calligraphy/"connecting the dots," (2) death and "your time is limited." Metrics: timestamp ranges, key-phrase coverage (N/3 target phrases matched), token estimate (chars/4), sentence-edge/contiguity check. Headline result: Q1 tied 3/3 key phrases but baseline mixes in an unrelated Stewart Brand passage from 10 minutes later; Q2 baseline scores 0/3 (pulls in the love-and-loss story) vs moment RAG 1/3 (correctly finds "you are going to die" but misses "your time is limited... don't waste it," which sits in a *different* moment, #12, that wasn't top-ranked). Token cost: ~188 (baseline) vs ~185–375 (moment, roughly 2x for the longer moment).

**5. Findings/limitations (his own):** Fixed windows reliably clip sentences and import neighboring stories. Moment RAG fixes mid-idea clipping but top-1 moment retrieval can still miss the *right* moment when an answer spans two pause-bounded segments (Q2 case) — pause boundaries don't guarantee ranking picks the correct one. Proposed next step: consider the "following moment" when a question asks for what comes after a pause. Token cost roughly doubles for longer moments.

**6. Honest assessment:**
- **Strongest:** Rigorous, reproducible quantitative comparison (checked-in scorecard: token counts, key-phrase hit rates, exact timestamps) on a real, non-trivial transcript, plus an honest failure case (Q2) rather than cherry-picked wins — a real bar to beat on evaluation discipline.
- **Weakest:** No actual LLM in the pipeline at all — "answers" are formatted/stitched raw retrieval text, not generated; this sidesteps the harder RAG problem (does an LLM synthesize a better answer from moment context vs. chunk context?) and is a meaningful gap if our submission does generate answers.
- **Exploitable gap:** Moment detection is purely rule-based (silence gap + keyword cue list), not LLM-assisted/semantic — brittle to videos without clean pauses or explicit verbal cues; also top-1-only moment retrieval (no re-ranking or multi-moment stitching) is an acknowledged, unaddressed weakness we could beat with smarter retrieval.
