# Recon: 001. Agentic Router.ipynb (50 cells)

## a. What it builds
Data sources (3): OpenAI docs (Qdrant collection `opnai_data`), 10-K filings — Lyft 2024 & Uber 2021 SEC filings (Qdrant collection `10k_data`), and live internet search via SerpApi (cell 7). LLM: OpenAI client, model string `"gpt-5.6-luna"` (cells 12, 23, 44) — used for routing, RAG synthesis, and sub-query splitting. Embedding model: `nomic-ai/nomic-embed-text-v1.5` via HuggingFace `transformers` (cell 21), mean-pooled token embeddings. Vector store: Qdrant, `AsyncQdrantClient` pointed at a local prebuilt path (`Agentic_RAG/qdrant_data`, cell 19) — no re-embedding needed. API keys expected (names only): `OPENAI_API_KEY`, `SERP_API_KEY` (loaded via Colab `userdata` or local `.env`, cell 4/6/11).

## b. Router logic
`route_query()` (cell 12) sends the user query to the LLM with a system prompt classifying into `OPENAI_QUERY`, `10K_DOCUMENT_QUERY`, or `INTERNET_QUERY`, returning JSON `{action, reason, answer}` parsed via regex + `json.loads`. Single-source only — no built-in multi-source split at this stage. `agentic_rag()` (cell 27) dispatches via a `routes` dict mapping action → handler (`retrieve_and_response` for the two Qdrant routes, `get_internet_content` for internet). `retrieve_and_response()` (cell 25) embeds the query, queries Qdrant (`limit=3`), then calls `rag_formatted_response()` (cell 23) which prompts the LLM to answer using only the retrieved context and cite sources as `[1][2]…`. Internet route returns SerpApi snippets with `Source:` links, not the same `[N]` citation format.

## c. RBAC / caching (existing)
RBAC: Section 6 (cells 33-41) adds `USERS` (user→role dict), `ROLE_PERMISSIONS` (role→allowed route labels, allow-list, deny-by-default), `has_access()`, `allowed_sources()`, and `secure_agentic_rag()` which gates the router's chosen route against the user's role before retrieval runs. Two roles: `engineer` (OpenAI docs + internet) and `finance_analyst` (OpenAI docs + 10-K). Caching: **not present** in this notebook — cell 41 explicitly warns that a shared semantic cache keyed only on the question would leak `bob`'s finance answer to `alice`, and defers real caching to notebooks `002. Semantic Caching.ipynb` / `003. Agentic Router_semantic_caching_rbac.ipynb`.

## d. Sub-query division plug-in point
This is the **required, ungraded-stub assignment** (cells 42-46). Reference splitter `sub_queries()` (cell 44) already exists (LLM call returning `{"subQuestions": [...]}` as a raw string). The stub `agentic_rag_multi()` (cell 46, currently `raise NotImplementedError`) is where it plugs in: parse `sub_queries()` output defensively (handle prose/code-fence wrapping), call `route_query()` + the existing `routes` dict per sub-query (same functions `retrieve_and_response`/`get_internet_content`, unmodified), then compose one answer preserving each sub-answer's citations. Single-question case must short-circuit to no extra LLM calls.

## e. RBAC-aware semantic cache plug-in point
This is the **optional bonus** (cells 47-49), also a stub. `RoleAwareSemanticCache` class (cell 48, `NotImplementedError` throughout) and `secure_agentic_rag_cached(user_id, user_query, cache)` are where it plugs in — order must be identity → route → RBAC permission check → cache lookup → pipeline (denials never cached, time-sensitive queries never cached). Touches `USERS`/`ROLE_PERMISSIONS`/`has_access()` from Section 6 and wraps `secure_agentic_rag()`'s logic. A self-check (`run_self_check()`, cell 49, commented out) asserts no cross-role leakage including paraphrase attempts. Notebook points to `rag_helpers.py`'s `SemanticCaching` (FAISS-based) in the not-yet-fetched notebook `003...` as the reference to extend/partition.
