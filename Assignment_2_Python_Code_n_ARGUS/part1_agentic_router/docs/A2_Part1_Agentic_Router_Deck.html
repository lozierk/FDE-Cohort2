2 · Sub-query division · design

Each sub-query runs the same router and routes; citations are renumbered so they never collide.

1 · Split
sub_queries()

Defensive parser strips fences and prose. Any failure falls back to the original query. Cap of 5.

→
2 · Route each
route_query()

Same router, same route table. Sub-queries may land on different sources.

→
3 · Answer each
Retrieve, then answer

Concurrent via asyncio.gather. Citations [n] become [i.n] for sub-query i.

→
4 · Compose
One LLM call

Keep every [i.n] verbatim. A Sources footer maps each marker to its snippet.

Composed answer, case 2 (from the run)

"In 2021:
- Lyft revenue: $3.208 billion (approximately $3,208,323,000).[1.2]
- Uber revenue: $17.455 billion (approximately $17.5 billion).[2.1][2.2]"
Sources footer lists [1.1]–[1.3] and [2.1]–[2.3], each with the 10-K snippet behind it

The single-question case

  • One sub-query skips the compose call.
  • LLM calls: split, route, answer.
  • That is one more than agentic_rag(), the split the brief allows.
  • Markers revert from [1.n] to [n].
Source: Part 1 implementation cell, design notes; check-yourself output, case 2
Renumbering before compose is the key choice. Two sub-answers both cite [1]; without a prefix, the composer cannot keep them apart and the trail breaks.

3 · RBAC semantic cache · design

Permission is checked before the cache is read, so a denied user never reaches a cached answer.

1 · Identity
Unknown user?

DENIED. No embedding, no cache, no LLM.

→
2 · Route
route_query()

Which source does this question need?

→
3 · Permission
has_access()

DENIED before any cache lookup. A denial is never cached.

→
4 · Cache
Same route, permitted rows

HIT returns the stored answer. MISS runs the pipeline, then stores.

Design choice: tagged by source, not by role

  • Each entry stores the route that produced it.
  • A lookup sees only rows from routes the caller may read.
  • alice and bob share OPENAI_QUERY rows; per-role caches would compute them twice.
  • Role change: nothing to flush. Permissions are re-checked on every request.

What is never cached

  • Denials.
  • INTERNET_QUERY answers: live search is time-sensitive by nature.
  • Time-sensitive wording: "latest", "now", "stock price" and similar.
  • Anything the caller could not read (checked again on store).
Source: Bonus implementation cell, RoleAwareSemanticCache docstring · similarity: cosine over nomic embeddings, hit at cosine distance ≤ 0.2
The brief offered two designs: partitioned per role or tagged. Tagging by source keeps one cache, shares the rows two roles may both read, and leaves protection to the permission check that runs first.

A HIT is not free: the router runs before the cache, so a HIT costs one LLM call plus an embedding. That is why bob's HIT is about 1.2 s, not near zero. Both HITs here were exact repeats (similarity 1.0).

5 · Limitations and production changes

This works for a notebook; production needs a shared, tuned, expiring cache.

limitationproduction change
In-memory cache (Python lists): lost on restart, one process onlyShared store, e.g. Redis or a vector DB, across workers
Threshold not tuned: cosine distance 0.2; live HITs were exact repeatsSweep on a paraphrase set; measure false hits and misses
No TTL or eviction; freshness rests on a keyword regexTTL per source; invalidate 10-K rows when the index is rebuilt
Router runs before the permission check: a denial still costs about 1 sPass the role's allowed sources into the router prompt
Gates whole sources, not chunksQdrant payload filters, so restricted chunks never enter context
Brute-force numpy searchfaiss.IndexFlatIP beyond about 10k rows
Audit log in memoryAppend-only store; that trail is what an auditor needs
Single runs. Each timing is one sample. The 1.37× concurrent speed-up and the 2944 → 1227 ms cache gain are indicative, not averages.
Source: Bonus cell design notes; notebook Section 6 "Where this is still weak"; leak-test timings. README.md lists no limitations.
The first two rows matter most. A shared cache is what ARGUS will need, and a similarity threshold chosen without a sweep is a guess, whether it errs toward false hits or toward misses.
