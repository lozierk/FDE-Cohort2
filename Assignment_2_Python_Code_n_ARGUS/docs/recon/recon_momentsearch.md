# MomentSearch Recon (for a simplified Moment-RAG pipeline)

## 1. Ingestion pipeline (video)
Prefect flow `ingest_video` (momentsearch/src/ingest/pipeline.py:161-181), stages:
fetch (162, `t_fetch` :41) → sample (170, `t_sample` :70) → embed-index (171, `t_embed_index` :98) → transcript (173, `t_transcript` :126, runs last, best-effort).
- **fetch**: yt-dlp download or bucket pull, hash for dedup (pipeline.py:41-66).
- **sample**: ffmpeg pipes keyframes to memory (interval or scene-cut; `src/ingest/frames.py:1-9`), pHash-dedups (`src/ingest/dedup.py`), uploads thumbnails (pipeline.py:69-94).
- **embed-index**: CLIP-embeds surviving frames in batches, upserts to Qdrant (98-122).
- **transcript**: yt-dlp captions (manual or auto) → json3 parse → chunked into ~20s passages → bge embeddings → separate Qdrant text collection (`src/ingest/transcript.py:1-101`, `pipeline.py:125-158`).
**No LLM anywhere in ingestion.** The only LLM call in the repo is at read time (`src/llm.py`) for answer synthesis — it takes retrieved "moments" (frame image + transcript text) and writes a cited answer; ingestion itself is pure CV/ASR-caption + embedding, no summarization or captioning LLM call found.

## 2. What a "moment" is
Not a stored row — **constructed at query time** by fusing two independent hit streams. No moment table/object persists in Postgres or Qdrant; Qdrant stores raw per-frame and per-transcript-chunk points (`src/rag/vector_store.py:1-22`), each tagged `modality: frame|text`. At retrieval, `_fuse()` (`src/rag/search.py:40-112`) buckets a frame hit and a transcript hit into the same "moment" if they're within `FUSION_WINDOW_S` (default 15s) of each other on the same video — a **fixed time-window heuristic**, not semantic/topic-shift or LLM-based boundary detection. A moment's transient fields: `video_id, t (start), page (None for video), frame, text, modalities, rrf score`. No fixed "moment duration" is stored — it's an anchor point (a frame timestamp or transcript-chunk start) plus a proximity window used only for grouping, not a persisted span.

## 3. Retrieval path
Two parallel branches, no single "moment embedding": (a) CLIP text→image search over raw frame vectors (`vector_store.search`, `rag/search.py:168`), (b) bge query→transcript-chunk search over raw chunk text (`vector_store.search_text`, :176), both same Qdrant instance/two collections, multi-tenant via `user_id` payload filter (`vector_store.py`). Ranking: Reciprocal Rank Fusion per branch (`RRF_K=60`), cross-modal boost (×1.5) when a frame and transcript both land in the same window, diversity cap `MAX_PER_SOURCE=3` (search.py:40-112). Trimmed to `TOP_K` (default 6) citations, each carrying a timestamp (`_seconds`, :27-29) or deep-link (`_deeplink`, :130-135) and thumbnail. Confidence gate: abstain without calling the LLM if best CLIP score < 0.2 AND best bge score < 0.35 (search.py:297-301, `ask()`). LLM prompt (`src/llm.py:36-77`) requires citing `[n]` per moment and grouping same-point moments together.

## 4. Eval / benchmark patterns
`momentsearch/eval/golden_set.json` — 14 hand-written queries (5 video-only, 5 doc-only, 4 mixed-corpus), each with `expect: [{source_id_pattern}]` and an informational (unscored) `locator_hint`. `scripts/run_eval.py` computes **recall@10** (top_k forced to 10 vs app default 6) with a hit rule: video/doc queries need ≥1 expected source in citations; mixed queries need ≥1 video AND ≥1 doc match (stricter, to prove real fusion) (run_eval.py:1-60). Target recall ≥0.85 (docs/bench/README.md). Separate **human faithfulness pass**: script writes `citation_check_<run-id>.md` listing every answer + locator for yes/no judgment, target ≥0.90 supported. Reusable pattern for chunk-RAG vs moment-RAG comparison: keep the same golden set/queries, swap only the retrieval+fusion layer, and score recall@k + a human citation-accuracy sheet — corpus-agnostic and doesn't require internal instrumentation (end-to-end HTTP only, per docs/bench/README.md).

## 5. Kurt's prior conclusions (from the three docs/ briefs)
- **Repo_Recon_20260728.md**: MomentSearch is built on five "rented managed services" (Neon Postgres, Prefect Cloud, Qdrant Cloud, object storage, a vision LLM) by design; search works with zero API keys (CLIP local, bge local, similarity-only fallback with no LLM configured).
- **Brief_Architecture_Considerations.md**: Frames the pipeline around 4 principles — a queue (Prefect) separating intake from execution, a managed-vs-self-hosted "bake-off" for that queue, fair queueing so one big backfill can't starve other tenants, and an index design using scalar quantization + a two-tier (RAM/disk) vector store.
- **Brief_Class_Deck.md**: Frames the assignment as building a scalable multimodal RAG pipeline with distinct INGEST (write) and QUERY (read) paths, with Qdrant configuration and multi-source (mixed corpus) grounding explicitly called out as an unspecified design decision left to the builder.
